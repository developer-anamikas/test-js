/* ## Understanding 'this' and `.bind(this)` in JavaScript Event Handlers (7:02-10:20) * **The Context Shift Issue**: * When you define a method (like `handleClick`) inside a class, `this` refers to the **class instance**, allowing you to access properties like `this.server`. * When you pass that method as a callback to an `addEventListener`, the execution context changes. * When the browser triggers the event, it sets `this` to point to the **HTML element** (the button) that was clicked, rather than your class instance. * **Why `this.server` becomes `undefined`**: * Because `this` now refers to the button element, JavaScript looks for the `server` property on that button. * Since the button does not have a `server` property, it returns `undefined`. * **The Solution: `.bind(this)`**: * Using `.bind(this)` (9:31) creates a new version of the function where `this` is **permanently locked** to the original class instance. * This ensures that no matter what triggers the function, `this` always points back to your class, keeping your data (like `this.server`) accessible. */ React
